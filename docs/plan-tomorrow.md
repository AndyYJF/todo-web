# 规划明天 · Web 与 Android 功能计划

日期：2026-11-21（新加坡时间）。服务端基础、双端排程、完成状态与历史补记已完成本地验收。

## 对抗审查修正

| 问题 | 第一阶段约定 |
| --- | --- |
| P0 凌晨补记与归档同时发生 | 同一日期只保留一份权威日记录。日记录保存课程快照，到 UTC+8 04:00 才标记归档。归档、补记和超额清理均走 SQLite 写事务，按 UTC+8 统一定日。 |
| P0 误删其他业务与旧数据复活 | 额度只针对已归档的 UTF-8 日快照。按日期整天删除，历史日只有还存在时才可补记。旧请求收到已清理或版本冲突。 |
| P1 数据丢失、超时重放、重复导入 | 条目级版本比较和独立的课表版本。操作 ID 与请求摘要绑定，同 ID 不同内容返回冲突。预览用原文件摘要和课表版本确认，重导只应用文件覆盖日期内尚未归档的课程。 |
| P1 课表周次与官方校历不一致 | 文件里的绝对日期决定上课时间。官方校历用于标注，不平移或删除导入课程。校历周按官方表格的星期日分行，标注考试、实践周。社区数据明确标注来源。 |
| P1 不完整导入覆盖现有课表 | 限制正文与展开量，无法识别的时间、重复标识或课程记录返回导入错误。原始 .ics 和导出器扩展字段不入库，附件只用于隔离验证。 |

## 使用流程

1. 从 WakeUp 导出课程日历，在 Web 或 Android 任一端导入。预览下一次上课日期、时间和教室，确认后发布课表，两端读取同一份结果。
2. 晚上通过 Android 提醒进入明日计划，也可以随时从两端主动打开。页面先铺出课程和空档，再把工作安排到指定时间，或者先放进「待安排」。
3. 第二天从「今天」进入同一份计划。一点即可完成，点开条目可标记未完成或补一句结果。次日凌晨 4 点前仍可直接勾选，4 点后系统自动归档。
4. 用「历史」回看某天的课程、安排、完成状态和备注。需要补记时从历史页主动进入编辑。

## 导入课表

- 首版支持 WakeUp 导出的 iCalendar（.ics）文件，也允许粘贴同样的 iCalendar 文本。沿用「粘贴或选文件 → 预览 → 确认」的短流程。WakeUp 另有 App 内使用的在线分享口令，目前核对的官方用户文档没有确认第三方兑换接口。取得可用的官方接口与样例后再决定是否支持直接粘贴 WakeUp 分享口令。[WakeUp 导出课表](https://www.wakeup.fun/doc/export_schedule.html) · [WakeUp 导入课表](https://www.wakeup.fun/doc/import_schedule.html)
- 上传文件或粘贴文本都由同一个服务端解析器处理。预览课程名、开始结束时间、教室、覆盖日期和无法解析的项目。检查重复规则、调停课例外与时区，按有界日期范围展开为课程实例。缺时区或跨日的事件在预览中提示。导入课程事件时忽略文件内的提醒规则，规划提醒走 Todo 自己的设置。[iCalendar 规范](https://www.rfc-editor.org/rfc/rfc5545.html)
- 首版保留一套生效课表。重新导入时预览文件覆盖日内今天及以后的新增、变更和移除，用户确认后应用。按课程事件标识、实例日期和时间去重。今天以前已有记录、手动排好的工作和备注保持原样。课表调整与工作时间重叠时高亮提示，由用户调整。
- 提供的课表标记生成器为 SleepDown，含 170 条已展开的课程实例，起止时间使用 Asia/Shanghai。已通过这份样本与合成的周重复/排除日期样例验证。对按其他方式表达的重复事件或 WakeUp 其他版本导出仍需用相应样本验收。

## 跨端同步

复用现有 Todo 登录、同源 API 和服务端 SQLite。在同一数据库新增课表、日计划、历史归档和提醒偏好。按 UTC+8 确定业务日期，日计划使用日期键，例如 `2026-11-22`。课程导入时完成时区转换，两端都用同一业务日期计算今天和明天。

| 数据 | 服务端表示 |
| --- | --- |
| 课表 | 导入版本与按日期查询的课程实例。课程提供时间占用和地点 |
| 日计划 | 每日一份，条目具有稳定 ID、可选起止时间、状态、结果备注和版本号 |
| 归档 | 每日一条快照，含课程、计划项、状态、备注、日期及字节数 |
| 提醒偏好 | 规划提醒开关、时间、业务时区。系统通知和精确闹钟的实际权限由各手机独立管理 |

1. **读取**。打开页面、App 回到前台、下拉刷新和写入成功后读取。规划页面可见时沿用约 30 秒的轻量刷新。今天和明天按日期读取，历史列表按日期分页，打开某天才读取正文。同一次写入返回服务端最新版本。Android 离线可看近期快照，网页和 App 都可保留尚未保存的草稿。
2. **写入**。创建计划项、调整时间、勾选状态、编辑备注分别提交具体改动，禁止整天无条件覆盖。条目更新携带上次读到的版本。不同条目可独立保存，同一条被另一端先改时显示当前记录和本端修改，可选择继续编辑。加、删、移动等需要多步落库的操作在单事务完成。移动到另一日与删除使用版本校验，旧端刷新不会把已删记录重新创建。
3. **重试**。新建、导入确认等写请求带客户端生成的操作 ID，用于服务端去重。发送成功但响应丢失时可按操作 ID 核对结果。断网期间保留草稿，恢复联网后再确认提交。慢速读取只应用到仍然匹配的日期、会话与请求版本，表单中的草稿独立保留。
4. **与 Todo 的关系**。日计划可以添加临时工作，也可以引用已有 Todo。日计划的勾选和结果用于记录当天实际执行情况。引用项保留当时标题用于历史回顾，即使原 Todo 后来改名或删除。首版不自动对原 Todo 写回完成状态，避免修改日期安排时产生意外的任务状态变化。

## 自动归档与 500 MB 滚动清理

- 每天以 UTC+8 凌晨 4 点为截止，自动归档前一天保存过的日计划。0 点切换今天和明天。0 点到 4 点在今日页提供「昨天待补记」入口，昨天仍按普通日期编辑。服务端运行时做清理和归档检查，启动与读取相关页面时兜底补跑，离线设备无须同时在线。以业务日期为归档唯一键。保存日计划时保留课程快照，跨日归档标记与滚动清理在同一事务提交，重复执行不会生成两份。
- 曾经标成「未完成」与当天没有记录结果的项目分别展示。默认只回顾，选择「补记」可以更新已有档案，继续走版本校验以及容量计算。过期的旧客户端写入在服务端按日期查找已有档案，版本不符或档案已清理时提示并保留本地草稿，不重建旧日。
- **先按 500 MB = 500,000,000 字节规划，额度只计算已归档的规划数据。** 按最终存入的 UTF-8 快照计算字节数，包含归档中的时间线、状态和备注。归档或补记后超过额度时，在同一事务中按计划日期从最早开始逐天删除，直到回到额度内。当天和未来计划、原课表与 Todo 数据不参与淘汰。首版只保存文本和课表字段，约束单日快照远小于总额度。
- 历史页显示最早可回顾日期和当前用量。客户端联网后以服务端历史列表为准，移除已回收的缓存。500 MB 是历史内容额度，SQLite 空闲页、索引、WAL 和其他业务表另占空间。删除后的空闲页供数据库复用。[SQLite 空间回收说明](https://sqlite.org/lang_vacuum.html)

## 夜间提醒

- 建议初始时间为 21:30（UTC+8），可修改，可关。Android 第一次启用时申请现有通知权限。设置保存到 Todo 服务，手机用最近同步的配置注册次日规划提醒。
- 在现有原生提醒模块上加独立的「规划明天」通知类别，按预定晚间日期去重。点击通知直达当时提醒所指向的日期，如果第二天才点也打开那一天。改时、关闭、重启及退出账号时更新或取消调度。
- 本地提醒可在无网时弹出，连续运行依赖系统调度。若系统延后到跨日，直接略过当晚过期的提醒。没有准时权限时使用系统允许的非精确闹钟。网页提供手动入口和提醒设置，不另发网页通知。[Android 闹钟说明](https://developer.android.com/develop/background-work/services/alarms)

## 双端界面

共同结构为「今天｜明天｜历史」。从今日入口默认看明天，从今日执行入口默认看今天，从提醒打开时按通知日期定位。时间线上用标签区分「课程」「工作」「空档」，每个空档提供添加入口，未填时间的工作放在「待安排」区。课程重叠用文字和颜色提示。已完成可以收起，未完成与未记录结果分别计数，备注可随时从条目打开。

| | Web | Android |
| --- | --- | --- |
| 入口 | 现有侧栏新增「规划明天」，今日页提供快捷入口 | 「今天」页加规划入口，「更多」中保留常驻入口，继续用现有导航 |
| 明天 | 延用 Web 的暖纸色、墨色主按钮、克莱因蓝强调色与 Motion 转场。宽屏左侧时间轴、右侧待安排和表单，窄屏纵向排列 | 延用 FlClash/Prism 卡片、分段控件和吸附面板。单列时间轴，点空档打开底部表单并预填时间 |
| 今天 | 在时间轴上直接勾选，右栏写结果或改为未完成 | 每条工作一键勾选，点开底部面板记录未完成原因或完成内容 |
| 历史 | 日期列表显示完成数，选中日期后并排查看原计划 | 按日期列卡片，点进完整时间轴，可向前翻日或跳到指定日期 |

示例。08:00–09:40「高数 · 教学楼 302」显示为锁定课程。下面的「09:40–11:00 空档」点一下就能添加工作。第二天打开「实验报告」时，勾选后可补一句「已提交第一版」。历史保留原来排定的时间和实际结果。

## 第一阶段接口与验收记录

所有规划接口沿用 Todo 的同源 Cookie，会话失效返回 401。客户端用读取响应里的毫秒级 `serverTime` 建立 `issuedAt`，并为每次提交生成一个 `operationId`。七天内用相同请求与相同操作 ID 重试，读取回执。超过重试窗口保留编辑草稿并从最新数据重新提交。版本冲突统一返回 409。

| 接口 | 客户端契约 |
| --- | --- |
| `GET /api/planner?date=YYYY-MM-DD` | 日计划、课程、全局版本与最早开放日期 `openFrom`。例如凌晨 2 点的 `openFrom` 是昨天 |
| `POST /api/planner` | `create/edit/delete/move`，创建传 `fields`。编辑、移动和删除传 `itemId` 和 `baseVersion`，移动加 `targetDate`。归档后编辑现存条目传 `correctHistory: true` |
| `GET /api/planner?view=history&before=...&limit=20` | 日期游标、每日报表计数、已用字节、额度和最早日期 |
| `POST /api/planner/timetable` | `preview` 发送 `ics`。 `commit` 同时传文件、预览的 `checksum`、`effectiveFrom`、`baseVersion` 和操作 ID |
| `GET/PUT /api/planner/settings` | 读取及版本化保存 `enabled`、`time`。Android 闹钟接线在第 4 阶段 |
| `GET /api/planner/academic-calendar?date=YYYY-MM-DD` | 周次、教学/考试/实践阶段、教务处公告与数据来源。当前学年用核对过的官方图表。新学年自动发现教务处公告，并读取 Bugaoshan 发布的结构化数据，标注为社区来源。仅有新公告时展示原文并等待结构化周次数据。两路各自缓存，失败使用最近成功的资料 |

川大官方图表按星期日开启新周。2026 年 11 月 21 日为第 12 周，11 月 22 日进入第 13 周。课表附件里的周标签不用于覆写官方周次，官方周次也不调整个人课程日期。[四川大学 2026–2027 学年校历](https://jwc.scu.edu.cn/info/1101/10727.htm) · [教务处校历索引](https://jwc.scu.edu.cn/cdxl.htm) · [Bugaoshan 校历数据](https://github.com/The-Brotherhood-of-SCU/Bugaoshan/blob/main/assets/academic_calendar.json)

本地验收包含两套独立登录会话通过真实 Next.js HTTP 接口交叉读取、同时写入不同条目、竞争同一个版本、移动后旧请求冲突、导入并发和幂等。SQLite 测试覆盖零点和 04:00 边界、归档补记、过期请求、按 UTF-8 字节计数与最早日期轮转。容量测试使用 480 字节额度走同一生产算法，生产配置仍为 500,000,000 字节。Next.js 生产构建通过，独立产物冷启动在任何 API 请求前自动补归档。

个人课表用于本地测试，仓库中只保留合成用例。

## 第二阶段验收记录

Web 从侧栏或今日页进入。Android 从「今天」或「更多」进入，沿用 Prism 的导航、卡片与底部表单。两端用服务端的 UTC+8 业务日期定位明天，都支持导入 .ics 文件或文本并预览、从空档预填时间、引用已有待办、改时间、移到另一日期或先保存为待排程。规划页可见时约每 30 秒刷新，也能手动刷新。Android 保存最近的日快照，离线期间可以继续查看。

使用 Web 浏览器和 Android 模拟器的独立登录会话连接同一个隔离 Next.js 服务。Web 导入合成课表后 Android 读到课程和安排。Android 通过系统文件选择器重新导入课表后 Web 读到更新。Web 先改备注，Android 保存旧版本时显示冲突，按最新版本继续后保留两端改动，并在两端提示课程重叠。验证了 Web 和 Android 各自跨日移动且原日期移除旧条目，Android 重启后恢复本地草稿，Android 新建待排程工作后 Web 可读。

## 第三阶段验收记录

两端可以直接勾选或撤销完成。打开条目可标为「未完成」或填写结果备注。「未记录」保留为独立状态，完成项可以收起。历史按日期分页，显示完成数、最早保留日期和归档用量。打开已归档的日期后，可以补记已有条目的状态、备注、标题和时间。档案仍使用原日期和归档时的课程快照。

在同一隔离服务上用独立的 Web 浏览器和 Android 模拟器会话互相读取勾选状态及备注。分别用 00:02 与 04:00 后的模拟业务时钟验证昨天入口和历史切换。编辑跨过归档边界时可以保留原输入，经主动确认后转为归档补记。丢弃已落库请求的响应后，Android 重试原操作，条目版本没有再增加，并保留了 Web 随后写入的备注。并发补记收到版本冲突后，用最新版本合并状态和备注。Web 验证了历史分页与课表重导后原档案的课程快照，Android 验证了断网显示本机快照及恢复前台后重新同步。容量轮转继续通过缩小额度的服务端回归用例验证。

## 第四阶段实现与验收

Web 与 Android 共用版本化提醒设置，初始关闭，默认时间为 21:30（UTC+8）。手机定期读取设置，按最近一次同步配置安排系统提醒。它与新校园任务和到期提醒各自调度。通知不包含课程、备注或任务名称，点按后按通知中保存的日期打开日计划。同一晚只提示一次，跨日后略过过期提醒。

- 本地 standalone 构建验证了分步发布。第一步隐藏网页规划入口，原有登录、任务、项目、校园同步读取与新规划 API 均可用。完整构建启用 Web 规划入口和提醒设置。
- 一加 8T 通过独立测试包验证了两端设置回读、改时、息屏且无法连接 Todo 服务时送达一条通知、点按打开指定日期、关闭提醒和退出登录取消调度。该设备延后了开机广播，重启并第一次打开 App 后，离线恢复了原定时间。标准 Android 模拟器重启后通过系统广播自动恢复。
- Android 0.7.0 Release 已通过签名、包标识和 arm64 应用二进制校验，沿用 0.6.0 的证书。生产 VPS 离线，本轮验证和产物均在本地。
