## A6 后台同步与消息提醒

使用原生 AndroidX WorkManager work-runtime2.12.0，经现有 Flutter MethodChannel 接入；不启动 Flutter 后台引擎或常驻服务。设置页保持固定版 FlClash/Prism 风格。

- 后台同步约每30分钟读取 GET /api/tasks?view=all，需网络满足系统条件；可在设置中请求立即后台读取。只读取 Todo 服务，不触发校园同步、AI分类或任务写入。
- 用户确认“新校园任务＋截止时提醒”。三个独立开关默认为关闭，首次启用按当前任务建立基线，不批量通知历史任务；已过期任务不因启用设置而补发。
- 新校园任务按服务端 ID 去重；已完成任务不发送新任务提醒。通知只显示任务标题，不含备注或图片，锁屏采用私密可见性。
- 截止时间按既有 UTC+8 语义转换为系统时间。允许准时提醒时使用精确闹钟，否则使用可延后的系统闹钟。完成、删除、取消时间或改期后重算/取消本机提醒。
- 通知点击携带任务 ID 和 origin。热启动、冷启动进入对应详情；其他站点的旧通知不跳入当前站点。Android 自动合并摘要按系统行为打开首页，单条通知进入任务。
- 后台快照单独写入，不改主文件中的会话、草稿或待确认请求。快照绑定会话和前台写入代次；请求返回时再次核对状态版本，防止慢读取覆盖已确认修改。前台恢复时可导入较新快照，再进行普通在线刷新。
- 网络失败保留最近成功快照；后台401停止调度并要求重新登录，草稿保留。退出或切换站点取消旧任务、闹钟与通知；重新登录重建基线。
- 开机、升级与时间变更后恢复已知截止闹钟；WorkManager 恢复周期任务。返回 App 时也恢复权限变更后的调度。
- 设置展示最近尝试/成功时间、执行结果、提醒数量及通知/准时提醒权限，并提供对应系统设置入口。

## 时效边界

约30分钟是系统任务的申请间隔，不保证每次按点执行。省电、断网、系统限制及强行停止会影响后台时效；强行停止后需重新打开 App。精确闹钟权限及系统通知通道也会影响提醒。此次进程退出与重启验证不等同于长期息屏省电测试或所有厂商系统的保证。

官方依据：[WorkManager](https://developer.android.com/jetpack/androidx/releases/work)、[通知权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)、[系统闹钟](https://developer.android.com/develop/background-work/services/alarms)。

生产后端、同步周期与 Web 均无代码改动，不增加多用户、额外加密、备份或离线写入队列。
