# Android App 开发计划

状态：计划已完成对抗审查，A0/A1 已实现并通过模拟器验证；A2 尚未开始。
更新：2026-11-17（Asia/Singapore）。

## 1. 目标与已确认约束

将个人 Todo 扩展为 Android 客户端，与现有 Web 共用生产服务 `https://todo.fei.cx` 和任务数据。

- 首期覆盖 Android 手机及现有 Web 的多端使用；平板做自适应布局，其他 Flutter 平台留待后续需求。
- UI 与动效仅参考计划编写日的官方最新稳定版 **FlClash v0.9.3**。Web 只提供数据模型和 API：不复用 Web 的纸色、衬线字体、CSS、图标、卡片装饰或页面布局。
- A0/A1 使用内存演示数据，所有页面明确显示演示标识；不接生产 API，不保存真实任务或会话，不提前安装 Dio 和持久化依赖。
- 保持单用户密码登录，沿用现有生产 API 和 SQLite。
- 采用在线写入、服务端为准、本地只读缓存的首期方案。离线时可查看已缓存任务，草稿可保留，业务修改在联网后提交。
- 使用 HTTPS、系统证书校验及应用私有存储；会话持久化，密码不持久化。不增加多用户、额外数据库加密、自动备份或常驻后台服务。
- 本计划不调整现有 Web 的视觉或生产同步周期。

## 2. 技术方案

| 部分 | 首期方案 | 理由与范围 |
| --- | --- | --- |
| App | Flutter，工程放在仓库 `mobile/` | 与参考应用使用相同技术，独立于 Next.js 的 `app/` 目录 |
| SDK | 优先锁定 Flutter 3.47.6，Dart 随 SDK | 与 FlClash v0.9.3 发布参考一致；初始化时记录 Android SDK、JDK 和构建工具版本 |
| UI | `prism_ui` 固定到 FlClash 同一提交 | 复用连续圆角、导航、按压、路由和面板的完整交互，降低手工仿制偏差 |
| 网络 | Dio，集中在一个 Todo API 客户端 | 统一 Cookie、超时、401 和请求结果处理；仅访问本站 API |
| 状态 | Flutter 自带 ChangeNotifier/Listenable，少量共享 Store | Auth、Task、偏好设置分别管理，界面订阅必要状态 |
| 本地持久化 | 应用私有目录中的设置、会话与 JSON 任务快照 | 数据量较小，先不增加客户端 SQL 数据库与写入队列 |
| Android 包 | 首先交付个人使用的 arm64-v8a APK | x86_64 用于模拟器；min/target SDK 在初始化阶段按锁定 Flutter 模板记录 |

A0/A1 的外部运行依赖仅为固定版 `prism_ui`；Dio 与 `path_provider` 从 A2 实际接入网络和缓存时添加。系统动态取色按独立依赖是否必要再确定。单个 `todo_session` Cookie 用 Dart 原生 Cookie 解析保存，尊重服务端过期时间，并只发送到 Todo 服务的同源请求。

建议应用标识为 `io.github.andyyjf.todo`，显示名为 Todo；属于本计划的初始命名，可在首次打包前调整。

### 工程边界

`mobile/lib/` 下分为 `app`、`ui`、`data`、`features` 四个目录。`data` 包含 API、模型、会话和快照；`features` 按任务、日历、四象限、设置组织。UI 组件集中处理主题、圆角、留白和动效，不在各页面重复定义一套动画参数。

### 3.3 动效是首期交付内容

| 场景 | 实现要求 | 验收重点 |
| --- | --- | --- |
| 一级导航 | 采用 Prism NavigationDock 的透镜移动、按压抬起和拖动跟手 | 快速连续切换不中断成跳帧；松手后自然收敛，页面状态保留 |
| 一级页面内容切换 | 沿用同版淡入淡出节奏；库中 tab 基准为 220ms | 列表滚动位置不重置，不叠加整页大幅位移动画 |
| 按钮与卡片按压 | 使用 ElasticPress/库原生反馈，包含柔和膨胀、跟手和释放回弹 | 点击、长按、滑动滚动之间无手势冲突；不额外套统一缩小动画 |
| 详情进入与返回 | 采用库中的卡片/页面转场，支持交互返回及取消 | 中途取消能回到原位置；系统返回与路由状态一致 |
| 新建、编辑与日期选择 | 使用 FormSheet/SnapSheet 等原生面板和吸附行为 | 拖拽与内部滚动正确交接，键盘升降不遮挡保存区 |
| 完成、删除、插入任务 | 按任务 id 保持身份，局部状态与列表高度平滑变化 | 失败可恢复原条目；刷新不让整页重新播放入场动画 |
| 明暗主题切换 | 采用 ThemeCrossFade，沿用库的主题时长（200ms） | 没有白屏、文字闪烁或全列表逐帧重建 |
| 请求与加载 | 首次加载用库内骨架/指示器，后续刷新保持已有内容 | 不用动画掩盖错误；后台刷新不抢焦点、不打断正在编辑的草稿 |

动效参数优先复用库的 spring 和 easing。其 Dock 透镜 travel spring 的参考时长为 400ms、bounce 为 0.15；这些属于参考实现，不在 Todo 页面中重新散落一套数值。依据：[motion.dart](https://github.com/chen08209/prism_ui/blob/63450c0ac0e8e1b2c0f3ed4ad7926dc94e083185/lib/motion.dart)、[navigation_dock.dart](https://github.com/chen08209/prism_ui/blob/63450c0ac0e8e1b2c0f3ed4ad7926dc94e083185/lib/navigation_dock.dart)、[主题参数](https://github.com/chen08209/prism_ui/blob/63450c0ac0e8e1b2c0f3ed4ad7926dc94e083185/lib/theme_data.dart)。

跟随系统“减少/关闭动画”设置，保留状态反馈和可操作性。性能验证聚焦导航、面板、长列表、主题切换四条实际路径；按真机刷新率检查帧预算，转场期间延后不必要的列表更新。大字体、48dp 触摸目标和中文文本布局同时检查。[Flutter 可访问性说明](https://docs.flutter.dev/ui/accessibility)

## 4. 页面与首版功能

### 今天

顶部大标题与日期，下面是待处理/逾期摘要卡和当天任务列表。新增使用标题栏的主操作按钮打开表单面板。显示客户端最近拉取状态；校园同步状态采用独立标识。

### 任务

分段筛选全部、未完成、已完成和置顶，支持项目筛选及本地标题/备注搜索。点条目进入详情；完成按钮、优先级、截止时间和来源提示保持清晰。未完成列表可以从全量快照本地筛选，不虚构服务端尚不存在的 `view=pending`。

### 四象限

按 urgent/important 的业务含义映射四象限，并保留未分类分组。手机使用 FlClash 风格的分组卡片与分段切换，展开某象限的任务；宽屏可将分组并列。视觉上不复刻 Web 坐标轴、细线网格或纸色卡片。支持详情内改象限，长按拖动作为增强交互。

AI 分类调用现有服务端接口，默认只处理未分类任务；重新分类全部是明确的独立操作，不随刷新自动调用模型。

### 更多

入口包含日历、项目、设置。设置集中放服务器地址、会话、主题、客户端拉取状态、校园同步状态和手动校园同步操作。项目沿用现有字符串分组，不新增独立项目管理后端。

### 任务详情/编辑

支持标题、备注、起止时间、完成状态、优先级、项目、快速任务、置顶及象限。备注完整展示，支持链接和校园图片；图片通过本站 `/api/img` 获取。新建按现有 TaskInput 发送，象限调整通过现有 PATCH 处理。

### 范围顺序

- 首个可用版本：登录、今天、任务列表与详情、CRUD、跨端刷新、缓存只读、四象限与手动/AI 分类、日历和项目入口、主题和基础动效。
- 随后增强：AI 分类反馈完善、四象限拖动、甘特图、桌面小组件、到期通知、离线写入。后续项不阻挡在线客户端闭环。
- 首期不建设注册/多用户、Android 常驻同步、WebSocket 推送或新的备份系统。

## 5. API 与同步约定

### 5.1 复用现有接口

| 接口 | App 用途 | 处理要求 |
| --- | --- | --- |
| POST /api/login | 单密码登录 | 保存服务端返回的 todo_session 及过期信息 |
| POST /api/logout | 退出 | 清理本地会话与任务缓存 |
| GET /api/tasks?view=all | 获取完整任务快照 | 成功后整体替换缓存，能感知其他端删除 |
| GET /api/tasks?meta=projects | 项目列表 | 与服务端字符串分组保持一致 |
| GET /api/tasks/:id | 编辑前或按 id 查详情 | 404 显示已删除，不自动重建任务 |
| POST /api/tasks | 新建 | 正确处理 201；超时不自动重复 POST |
| PATCH /api/tasks/:id | 修改、完成、置顶、改象限 | 只发送用户修改的字段 |
| DELETE /api/tasks/:id | 删除 | 明确确认后提交；失败保留任务，不承诺当前 API 不支持的删除撤销 |
| GET /api/sync | 校园同步最近结果 | 与 App 自身拉取时间分别显示 |
| POST /api/sync | 显式请求校园同步 | 仅在用户点击该操作时调用，完成后重新拉取任务 |
| POST /api/classify | 分类未完成任务 | 默认未分类；force=1 会重新分类全部，UI 明确区分 |
| GET /api/img?u=... | 备注图片 | 通过本站鉴权代理，不向第三方图片域发送本站 Cookie |

当前源码依据：`app/api/**/route.ts`、`lib/types.ts`、`lib/tasks.ts`、`lib/auth.ts`、`lib/campus-sync.ts`。

### 5.2 首期多端同步方式

1. 登录成功、启动、回到前台、下拉刷新和写入成功后拉取任务。
2. App 在前台时每 30 秒全量拉取；后台停止轮询。合并重叠请求，并按请求代次/写入代次丢弃过期响应，防止写入前发出的慢 GET 覆盖写入成功后的状态；编辑面板保留自己的草稿。
3. 任务全量响应替换本地快照，更新列表与计数。网络失败保留缓存并标记其时间，不显示虚假的已同步状态。
4. 新建/编辑/删除仅在联网时向服务端提交。按钮显示待提交状态并防重复点击；已确认失败的操作恢复原状态或保留草稿。
5. 对“请求已发出但响应超时”显示结果待确认，先重新拉取；不盲目重试新建，避免重复任务。
6. 首期同字段并发修改采用现有服务端最后写入生效的语义。当前 updatedAt 精度和 API 没有提供可靠的条件更新协议，不把它包装成冲突检测或强一致同步。
7. 若以后需要离线写入，再单独设计客户端操作标识、幂等提交、版本冲突与删除记录。

App 下拉刷新表示“从 Todo 服务读取”，不等于触发校园上游同步。服务端继续按原有十分钟周期对接校园平台。前台轮询与缓存回退属于本项目的轻量取舍，参考 [Flutter 的在线写入和缓存读取模式](https://docs.flutter.dev/app-architecture/design-patterns/offline-first)。

### 5.3 数据兼容注意点

- 响应中的 done、quick、pinned、urgent、important 包含 0/1，后两者可为 null；写入请求按现有 API 的 boolean/null 约定发送。
- 起止时间、createdAt、updatedAt 使用既有业务时区 UTC+8 的字符串语义；集中处理日期，不因设备时区变化而改写截止时间。
- 401 清理过期会话并返回登录，正在编辑的草稿保留；设置里只保存站点地址和会话，不保存密码。
- 会话与快照绑定 origin；切换站点先清理旧会话/缓存再重新登录，跨源重定向不携带 Cookie。明确退出时即使远程请求失败也清理本地会话；客户端退出不宣称已吊销其他设备会话。
- 修改校园来源任务的完成状态仍由现有服务器回写上游。App 不保存校园平台或模型服务凭据。
- 首期无需新增认证体系、同步数据库表或增量拉取接口。若实际联调发现现有接口缺少必须能力，先记录具体失败场景，再实施最小兼容改动。

## 7. 验证标准

1. 只登录一次后重启 App 会话仍可用，服务端失效后能重新登录。
2. Android 创建/修改/完成/删除任务，Web 刷新能看到；Web 的变化在 App 回到前台或下一轮刷新后可见，包括删除。
3. 刷新失败仍能查看最近缓存，编辑草稿不被后台轮询覆盖；离线业务写入有明确提示。
4. App 拉取时间与校园上游同步时间分开显示；GET 刷新不误触发校园同步或 AI 分类。
5. 导航、详情、编辑面板、完成反馈、主题切换均有与 FlClash 同版一致的动效语义；真机不出现明显卡顿、白屏或整页反复入场。
6. 系统返回、手势取消、键盘显示、明暗主题、大字体及减少动画下仍能正常操作。
7. 本地针对模型解析、会话失效、全量快照替换和写入超时做必要验证；UI 用关键流程录屏检查，不扩展成无关的全套审计。
8. 生产验证使用本人正常操作；自动化 CRUD 与故障注入放在本地开发后端。首版 App 主要复用生产 API，服务器若有改动则另列精确差异与验证结果。
