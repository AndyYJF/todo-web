## 结果

- 接入现有任务 POST/PATCH/DELETE 和编辑前按 ID 读取；支持标题、备注、项目、起止时间、优先级、快速任务、置顶及完成状态。编辑仅提交实际改变的字段，删除明确确认后发送。
- 业务修改等待服务端确认，失败保留任务/草稿；提交期间禁止重复操作。没有乐观删除、虚假撤销或自动重发。
- 全量读取带认证、写入和请求代次，丢弃写入前发出的旧 GET；写入结束后重新读取。
- App 前台每30秒读取，后台停止；启动、回到前台、按钮和下拉同样读取。
- 草稿独立于任务快照，关闭、重启或401后可继续；后台更新不覆盖表单。时间输入按UTC+8，日期快捷项继续采用 Prism 面板。
- 单笔待确认记录在请求发出前落盘。超时/连接中断/服务端5xx不自动重发。PATCH/DELETE可按最新服务端状态核对；未知新建仅显示候选并由本人确认身份。候选匹配不等同于可靠幂等识别。
- 未获得首次有效任务快照或当前使用失败后的缓存时，禁止业务提交；仍可保存草稿。

## 验证

使用现有 Next 后端、独立 SQLite（证据目录 local-web.db）、本地测试密码及关闭的校园上游配置。生产数据库和生产任务未用于自动化 CRUD 或故障注入。

1. 本地双客户端通过：Web侧创建→App读取，App部分修改→Web侧读取，同时保留另一端更新的备注；完成、置顶、起止时间、快速任务和删除均核对服务端结果。
2. 慢 GET 在写入成功后返回，没有覆盖新状态；双击提交只产生一次 POST，201正确处理。
3. 在服务端已写库后让 POST 响应超过20秒，客户端保留待确认记录，重复点击/刷新/重启都没有追加 POST；本人确认匹配的新任务后才结束确认。
4. PATCH 响应连接中断后，通过读取当前字段完成核对，没有重发 PATCH。404保留草稿且不创建替代任务；401清理会话并保留草稿，重新登录不自动提交。
5. 离线缓存以及首次读取失败均不发送业务 POST；恢复有效读取后可以提交。
6. 实际等待两轮31秒：前台有30秒轮询，切到后台后无轮询。
7. 本地真实界面：Web表单创建的任务出现在 App，App 表单草稿关闭/恢复后保存的任务出现在 Web；截图 web-app-sync.jpg 和 app-created-task.png。未发现 Flutter 运行异常。初次脚本在调试面板转场结束前过早检查，随后新层级及 Web 刷新确认创建成功。
